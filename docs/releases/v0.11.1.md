# Starfall v0.11.1 — final completion fixes

Starfall v0.11.1 fixes five defects found by the final completion pass over v0.11.0: character files can move
between independent servers again, 2014 Wizard multiclass characters get the right spell slots, and the logs, the
Compendium's accessibility and the maintenance scripts are corrected. No database changes.

## Fixes

- **Export/import between servers:** a character file exported from one Starfall server was refused by every
  other server, because the built-in elements (abilities, skills, saving throws and a few base rules) get their own
  ids on each install. Exports now carry those elements' rules, and imports match them by type and name; anything
  that doesn't match exactly is still refused. (#18)
- **2014 Wizard multiclass slots:** a 2014 Wizard multiclassed with another spellcaster got each class's slots
  added (Wizard 3 / Cleric 1 showed 6 first- and 2 second-level slots) instead of the multiclass table (4 and 3).
  The sheet, the PDF and the Magic tab use the table now. (#14)
- **Familiar log noise:** familiars' stat blocks (Find Familiar) no longer log errors about the missing
  `companion:proficiency` value; real failures are still logged as errors. (#13)
- **Accessibility:** the Compendium's filters have accessible names, and the battle page's use pips no longer
  misuse ARIA. (#15)
- **Maintenance scripts:** `verify.sh` and `restore.sh` accept a relative backup folder given from outside
  `deploy/`, and name the folder when it can't be found. (#17)

## Dependencies

- Dependabot alerts 59 → 9, none critical. The only runtime change is react-router 7.18.1 → 7.18.4; the 9 left are
  in build tooling and need major upgrades. (#16)

## Upgrading

No database migrations and no reprocess. Make and verify a backup, then update as described in
[maintenance](../maintenance.md) (`maintenance/update.sh`). Coming from v0.10.0, also run v0.11.0's one-time
`./admin.sh reprocess` (see the [v0.11.0 notes](v0.11.0.md#upgrading)).

Character files exported with v0.11.0 or earlier still import on the server they came from, but not on another
server: export them again after updating ([character portability](../character-portability.md)).

## Validation status

CI passes on every pull request (backend with the SQL Server tests, frontend tests, TypeScript check, production
build); all fixes merged together: 859 backend tests, 0 failed, 24 skipped; 256 frontend tests passed. On disposable
installs with the group's real Aurora characters: export from one server and import into a second, independent one
gave identical characters; the multiclass sheet matches a hand calculation; two axe-core (WCAG 2.1 A/AA) findings
are fixed and two minor ones are left (below); an install of v0.10.0 updated, verified, restored and rolled back. The
homelab runs this code since 2026-10-20 (every character identical before and after the deploy). Details: the
[final completion report](../ai/MK2_FINAL_COMPLETION_REPORT.md).

## Known limitations

- Windows (Docker Desktop/WSL2, `setup.ps1`) is still untested.
- An edit made in the first seconds after levelling, while the builder's save snapshot waits for processing, is not
  undone by Discard (it is kept, not lost).
- Resistance order can differ from Aurora's; Slate's destructive chip contrast is 4.42:1; the Characters cards nest
  their buttons in the card's control.
- Carried over: the transitive `System.Security.Cryptography.Pkcs` 9.0.4 NuGet advisory, existing lint debt (38
  errors, 1 warning) and large frontend bundles.
