# Starfall v0.11.0 — stabilization

Starfall v0.11.0 is the stabilization release of the v0.10.0 public beta. It fixes how characters' skills and
proficiencies are saved and shown, makes Aurora imports and homebrew changes safe against partial failures, and
brings the Starfall artwork to the home page and the app's decorations.

## Fixes

- **Skills:** on SQL Server a character could be saved with no skills at all, because the Skills rule could be
  processed before the Abilities rule and then skipped every skill. Rules are now processed in the order they were
  made, and missing skills and saving throws are repaired. Characters saved earlier get their skills back with one
  admin reprocess (see "Upgrading").
- **Sheet proficiency:** expertise and proficiencies that Aurora grants as statistics (Scout, Knowledge Domain,
  2024 Resilient and others) are marked on the interactive sheet and the PDF.
- **Aurora attacks** with an empty identifier (such as a renamed Mace) are kept with a stable fallback id, and
  "Update from Aurora" updates the same attack instead of adding another.
- **Aurora import** sets ability scores before equipment, so Strength-dependent armour rules (Chain Mail speed) are
  judged correctly.
- **Aurora imports and homebrew** uploads, replacements and deletions run in one transaction: a failure leaves the
  content as it was, and the content version changes only after the change is committed.
- **Compendium** no longer overflows horizontally on phones.

## Look

- Home page artwork for each theme (Midnight, Porcelain, Slate), following the selected theme without a reload.
- Theme pictures for page corners, dividers, dialog corners and the active navigation item. They are decorative only:
  hidden from screen readers, never clickable, absent from print, and only the current theme's files load.

## Development

- CI runs on pushes and pull requests again (`.github/workflows/ci.yml`), with a SQL Server 2022 service for the
  SqlServer test category and read-only workflow permissions.
- `aurora-server` accepts changes only through pull requests with passing CI; force pushes and deletion are blocked.

## Upgrading

No database migrations. Make and verify a backup, update as described in [maintenance](../maintenance.md), then run
the admin reprocess once (`./admin.sh reprocess`) so characters saved without skills get them
back. On the copies tested it changed nothing else.

## Validation status

The full backend suite, including the SQL Server tests, passes in CI on the merged code; frontend tests, the
TypeScript check and the production build pass. On disposable installs with 14 real Aurora characters: imports
through the browser, sheets against Aurora's own PDFs (no proficiency or expertise differences), PDF export, Battle
readouts, and the home page and decorations in every theme from 320 to 1920 px. The deployment was rehearsed on a
copy of the live database before it went live. Commands, numbers and live results are in the
[verification report](../ai/MK2_VERIFICATION_REPORT.md).

## Known limitations

- Not checked in a browser: Lore content, campaign editing, a real multiclass character, character export/import;
  no automated accessibility audit; Windows remains unverified.
- The artwork pack's Slate pictures are drawn for dark backgrounds and show only faintly on the light Slate theme.
- Carried over from v0.10.0: the transitive `System.Security.Cryptography.Pkcs` 9.0.4 NuGet advisory, existing lint
  debt and large frontend bundles, and the artwork redistribution note in the
  [v0.10.0 notes](v0.10.0.md#known-beta-limitations). The new home page and decoration pictures come from the
  owner's Starfall asset packs.
