# Starfall v0.10.0 — public beta

Starfall brings Aurora-compatible character building, campaign management and tabletop play to a self-hosted
browser application. This public beta combines the completed character, campaign, homebrew and installation work
on `aurora-server`.

## Included improvements

- Aurora custom attacks survive imports and retain their written figures and display order in character sheets,
  PDF exports and Battle. Natural-armor calculations include features such as an autognome's Armored Casing.
- Interactive sheets share play state with Battle. Spell selection has search, pagination and verified
  same-edition printing groups, preserving different editions and homebrew.
- Porcelain, Slate and Midnight themes, responsive navigation and the established celestial branding.
- Character export/import between compatible installations; campaign session search and collapsible navigation.
- Homebrew forms for items, monsters, spells, subclasses and classes. Encounter estimates distinguish 2014 and
  2024 rules, with an optional magic-item adjustment.
- Docker installation helpers, verified-backup tooling and guarded restore/update/rollback workflows.
- Repository OpenAPI description, Scalar viewer, developer integration guide and Python/TypeScript examples.
- PDF.js security update and compatibility with both legacy and wrapped 5etools book/adventure files; subraces that
  copy another subrace (the Amonkhet human) appear in the Compendium.

## Installation and upgrades

Use an x86-64 Linux machine with Docker Engine and Compose, Git, Python 3 and curl. Allocate at least 4 GB RAM to
Docker and 10 GB disk; 8 GB RAM and 20 GB disk are recommended. Windows uses Docker Desktop with WSL2/Linux
containers and remains unverified on real Windows hardware. ARM is unsupported. Internet access is needed for
images, dependencies and optional content downloads. Docker supplies the .NET and Node runtimes.

Follow [installation](../installation.md) and [maintenance](../maintenance.md). Make and verify a backup before
upgrading. The release-preparation compatibility patch adds no database migration; upgrades from older versions
can include earlier migrations. Use the maintenance preflight and preserve the rollback/restore instructions.
After the wrapped-book fix, rebuild imported lore through the existing content-update workflow to replace empty
chapter indexes. Do that only on an installation you are authorized to administer. 5etools 2.38 wraps every book and
adventure, so earlier builds showed all of them without chapters. The Compendium's build format went up (f8), so
the next content update (`./admin.sh update`, or the Content page) rebuilds it under a new version.

## Validation status

On the release commit: the full backend suite passes (803 tests: 779 passed, 0 failed, 24 skipped, including the
OpenAPI drift check and the wrapped-book tests); a clean `npm ci`, the full frontend build and 235 frontend tests with
real 5etools content pass; 39 installer tests pass; 19 PDF templates parse with a three-page synthetic export; CI ran
on the release commit. Built from 5etools 2.38, all 101 adventures and 67 books have their chapters. Not rerun on
this commit: browser journeys on a disposable install. `npm audit` advisories are limited to developer tooling and
react-router's unused server mode; the server's NuGet audit lists a transitive `System.Security.Cryptography.Pkcs`
9.0.4 (one high, one moderate advisory), to be updated in a follow-up (details in the report). The [verification report](../ai/V0_10_0_VERIFICATION.md)
records commands, environment limitations and provenance.

## Known beta limitations

- Custom attack numbers are preserved as entered, not recalculated. Finished weapon attack totals are computed by
  the web app; the API exposes their inputs. Some OpenAPI query parameters and admin response codes are incomplete.
- There are no accounts or read-only integration tokens. Lock players who need protection and keep the server on
  a private network. Scalar's repository viewer downloads its JavaScript from jsDelivr.
- Character transfers need matching content/homebrew. Campaign archives cannot yet be imported.
- Homebrew requires an initial content import; custom classes lack Mystic Arcanum, third-caster and custom resource
  support. Concurrent builder/Battle charge changes can leave a stale display.
- Windows/WSL2, a full content download through setup, exhaustive rules coverage and a full accessibility audit are
  not certified. Existing lint debt and large frontend bundles remain.
- No redistribution grant is on record for the bundled artwork (upstream's pictures in `public/images`, the
  background art in `public/art`) or the D&D logos on the Aurora sheet templates. The owner chose to publish them
  as they are (2026-10-16).
